<h1 align="center">GitCat</h1>

<p align="center">Быстрый настольный Git-клиент для Windows и macOS. Работает с GitHub, GitLab, Gitee, Gitea, Bitbucket, Azure DevOps и любым другим git-хостингом.</p>

## Возможности

| Раздел | Что есть |
| --- | --- |
| Изменения | Списки «в индексе / не в индексе» с фильтром, **индексирование по блокам и строкам**, единый или **двухпанельный** diff с подсветкой слов, разрешение конфликтов (наша / их версия / инструмент слияния), amend, sign-off, коммит и отправка |
| История | Граф коммитов с метками веток / тегов и аватарами, быстрый фильтр, глубокий поиск (сообщение / автор / код `-S` / путь), сравнение коммитов, blame, история файла, восстановление любой версии |
| Файлы | Просмотр проекта в рабочем каталоге или на **любой ветке, теге или коммите**, просмотр кода, поиск по содержимому (`git grep`), **сравнение любой версии файла с любой другой** (в том числе файлов вне репозитория) |
| Ветки и теги | Переключение, создание, переименование, удаление, upstream, слияние (ff / no-ff / ff-only / squash), rebase, **интерактивный rebase**, cherry-pick, revert, reset, bisect, теги (аннотированные / лёгкие, отправка / удаление на сервере) |
| Релизы | **Релиз в один клик**: находит файлы версии, повышает semver, обновляет `CHANGELOG.md`, коммитит, ставит тег, отправляет и показывает запущенный CI |
| Учётные записи | GitHub, GitLab, Gitee, Gitea / Forgejo, Bitbucket, Azure DevOps, любой хост. Вход по **токену**, через **браузер** (Git Credential Manager) или по **SSH**; изменение, проверка, выбор основной, выход; привязка учётной записи к репозиторию |
| CI и релизы | Статус заданий и шагов GitHub Actions, конвейеров GitLab, Bitbucket Pipelines и Gitea Actions; перезапуск, отмена, ручной запуск; список релизов; создание pull / merge request |
| Центр команд | **80 команд git** в виде форм с предпросмотром командной строки, ссылкой на документацию и подтверждением опасных операций, плюс свободная командная строка git |
| Ещё | Вкладки репозиториев, stash, рабочие деревья, подмодули, reflog, очистка, патчи, архивы, консоль git, палитра команд (`Ctrl+Shift+P`), аналитика, 4 темы, 10 языков, автообновление |

## Учётные записи и учётные данные

GitCat использует собственную систему учётных данных git, поэтому всё, что работает в командной строке, работает и здесь:

1. **Существующая настройка**: если `git push` работает в терминале (Git Credential Manager, Связка ключей, SSH-агент, `~/.ssh/config`), GitCat использует те же учётные данные без настройки.
2. **Окружение**: `GITHUB_TOKEN`, `GH_TOKEN`, `GITLAB_TOKEN`, `GITEE_TOKEN`, `GITEA_TOKEN`, `BITBUCKET_TOKEN`, `AZURE_DEVOPS_EXT_PAT` и CLI `gh` / `glab` определяются автоматически и импортируются в **Учётные записи → Окружение**.
3. **Учётные записи** (меню **Учётные записи**, `Ctrl+Alt+A`):
   - **Токен**: вставьте персональный токен («Создать токен» открывает нужную страницу у каждого сервиса); «Проверить» заполнит имя, почту и аватар.
   - **Браузер**: вход через окно OAuth Git Credential Manager (входит в Git for Windows).
   - **SSH**: выберите или создайте ключ `ed25519`, скопируйте открытый ключ, откройте страницу SSH-ключей сервиса и проверьте подключение.
   - Токены сохраняются в системном хранилище учётных данных через `git credential approve`. Хранение в конфигурации GitCat возможно, но выбирается явно.
4. **Несколько учётных записей на одном хосте**: «Использовать для этого репозитория» записывает `user.name`, `user.email`, `core.sshCommand` (SSH) или имя пользователя в HTTPS-URL только для этого репозитория.

Собственные экземпляры GitLab / Gitea / GitHub Enterprise работают, если при добавлении учётной записи указать имя хоста.

## Установка

Скачайте zip для своей платформы на странице [Releases](https://github.com/liu294100/git-cat/releases):

| Платформа | Файл |
| --- | --- |
| Windows 10/11 x64 | `GitCat-Windows-x64-onefile-v<версия>.zip` |
| macOS Apple Silicon | `GitCat-macOS-arm64-onefile-v<версия>.zip` |
| macOS Intel | `GitCat-macOS-x64-onefile-v<версия>.zip` |

Нужен установленный Git (Windows: [Git for Windows](https://git-scm.com/download/win); macOS: `xcode-select --install` или Homebrew). На macOS при первом запуске используйте правый щелчок → Открыть, так как приложение не нотаризовано.

Справка → *Проверить обновления* скачивает новый zip, проверяет его по `SHA256SUMS`, заменяет программу и перезапускает её.

## Запуск из исходников

```bash
python -m pip install -r requirements.txt
python -m gitcat [путь/к/репозиторию]
```

Требуется Python 3.10 или новее.

## Сборка

| Платформа | Команда | Результат |
| --- | --- | --- |
| Windows | `release.bat [версия]` | `release/GitCat-Windows-x64-onefile-v<версия>.zip` |
| macOS | `./release.sh [версия]` | `release/GitCat-macOS-<arm64\|x64>-onefile-v<версия>.zip` |

Оба скрипта создают `.venv`, устанавливают `requirements-build.txt` и запускают PyInstaller с `GitCat.spec` (значок, сведения о версии файла Windows, метаданные пакета macOS).

## Публикация релиза

1. Повысьте `__version__` в `gitcat/__init__.py` и добавьте раздел `## vX.Y.Z` в `CHANGELOG.md`.
2. Сделайте коммит и выполните `git tag vX.Y.Z && git push origin vX.Y.Z` или используйте 🚀 релиз в один клик в GitCat.
3. `.github/workflows/release.yml` проверяет совпадение тега и `__version__`, собирает Windows x64, macOS arm64 и macOS x64, создаёт `SHA256SUMS` и публикует GitHub Release с разделом CHANGELOG в качестве описания.

Ручной запуск workflow (`workflow_dispatch`) собирает пакеты как артефакты без публикации.

## Архитектура

```
gitcat/
├── core/        предметная область git без Qt: модели, запуск процессов, репозиторий, diff/патчи, граф,
│                разбор URL хостингов, обёртка git credential
├── services/    сценарии: снимки состояния, учётные записи, REST-клиенты сервисов, каталог команд,
│                релизы, автообновление
├── common/      локализация, настройки, ресурсы, интеграция с ОС, работа с текстом
├── ui/          PySide6: виджеты, диалоги, страницы, представление репозитория и mixin-операции, главное окно, тема
└── locales/     переводы <язык>.json
```

Зависимости направлены только вниз (`ui → services → core`, все слои могут использовать `common`). Вся работа с git выполняется в пуле потоков; при обновлении запросы на чтение идут параллельно, повторные запросы объединяются, история перезагружается только при изменении HEAD или ссылок, а `.git` отслеживается вместо периодического опроса.

## Разработка

```bash
python -m pyflakes gitcat           # статическая проверка
python scripts/check_locales.py     # все ключи есть во всех 10 языках
python scripts/generate_icons.py    # пересоздать assets/ (нужен Pillow)
```

Файл настроек: `%APPDATA%\GitCat\config.json` (Windows), `~/Library/Application Support/GitCat/config.json` (macOS).

История версий — в [CHANGELOG.md](CHANGELOG.md) (на английском).
